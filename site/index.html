A simple Lua interface to LLM models

Chat, streaming, tools, embeddings, structured output, and reasoning control across cloud providers, local Ollama models, and any OpenAI-compatible endpoint — behind a single normalized API, with the provider's own response always kept intact.

Get started Read the API

  • Lua 5.1 – 5.4
  • Cloud and local models
  • No API key needed to start

what it does

A complete LLM surface in Lua

Every provider is normalized to the same shapes, so text, tool_calls, usage, model, finish_reason, and provider mean the same thing everywhere. The untouched provider payload stays available on raw.

Swap providers, keep your code

OpenAI, Claude, Gemini, Grok, Groq, OpenRouter, DeepSeek, Mistral, and Ollama all answer the same call, and a custom endpoint joins them without waiting for a new adapter.

llm.new("claude"):chat(messages)

Real SSE streaming

Normalized deltas as they arrive, with correct handling for fragmented events, multiline data, retries, and timeouts — not a buffered response pretending to stream.

client:stream_chat(messages, on_delta)

Tools that finish the job

Define tools once with JSON Schema. The registry normalizes calls across providers, runs your handlers, and keeps going when the model needs a second tool to answer the first.

{ tools = tools, max_tool_rounds = 8 }

Structured output

Ask for a JSON Schema and read the decoded object back. One schema covers every provider, including Claude, which has no response-format field and needs a forced tool call instead.

client:chat(m, { json_schema = s })

Reasoning you control

Turn thinking down for latency, or up for hard problems, with one option instead of four provider dialects. A model that cannot comply still answers, and says so.

client:chat(m, { reasoning = false })

Embeddings

Create embeddings from a string or a batch through OpenAI, Gemini, Mistral, Ollama, or DeepSeek, and read them back in one result shape.

embeddings:embed({ "first", "last" })

Local-first development

Ollama needs no cloud account and no API key, so you can build and test the whole surface on your own machine before a single credential exists.

llm.new("ollama"):chat(messages)

Failures you can act on

Structured, redacted errors alongside retries, rate-limit headers, cancellation, lifecycle hooks, and request IDs. Credentials never reach your logs.

local _, err, details = client:chat(m)

Compatibility you can verify

Declare what a custom server supports, then run the bundled conformance suite against its real models, chat, and SSE endpoints to find out what it actually does.

lua scripts/conformance.lua

the api

Start with familiar Lua

Ordinary tables in, result, err, details out. No class hierarchy to learn and no framework to adopt. 

local llm = require "ug-lua-llm"

local client = llm.new("ollama", { model = "llama3.2" })

local response, err = client:chat({
  { role = "user", content = "Why is Lua a good embedding language?" },
})

assert(response, err)
print(response.text)

Swap "ollama" for "openai", "claude", "gemini", "grok", "groq", "openrouter", "deepseek", or "mistral". Nothing else in this file changes. 

local client = llm.new("claude", {
  api_key = os.getenv("ANTHROPIC_API_KEY"),
})

local ok, err = client:stream_chat(messages, function(delta, full)
  io.write(delta.content or delta.text or "")
  io.flush()
end)

Deltas normalize content, text, tool_calls, finish_reason, provider, and raw. Streaming falls back to a regular request when a server has no working SSE. 

local tools = {{
  name = "get_weather",
  description = "Get weather for a location",
  parameters = {
    type = "object",
    properties = { location = { type = "string" } },
    required = { "location" },
  },
}}

local response = assert(client:chat_with_tools(messages, tools))

for _, call in ipairs(llm.Tool.parse_tool_calls(response)) do
  print(call.name, call.arguments.location)
end

Parsed calls carry { id, name, arguments, type, raw }. Malformed JSON arguments are preserved rather than silently discarded, so you can decide what to do about them. 

local embeddings = llm.Embeddings.new("openai", {
  api_key = os.getenv("OPENAI_API_KEY"),
})

local result = assert(embeddings:embed({ "first", "second" }))

Available for OpenAI, Gemini, Mistral, Ollama, and DeepSeek. 

local response = assert(client:chat(messages, {
  json_schema = {
    name = "npc_reply",
    schema = {
      type = "object",
      properties = {
        line = { type = "string" },
        mood = { type = "string", enum = { "calm", "angry" } },
      },
      required = { "line", "mood" },
    },
  },
}))

print(response.parsed.line, response.parsed.mood)

parsed holds the decoded object and text the raw JSON. A model that cannot honour the schema still answers; structured_applied tells you which happened. 

-- Dialogue wants speed, not deliberation.
local reply = assert(client:chat(messages, { reasoning = false }))

print(reply.usage.reasoning_tokens)  -- 0
print(reply.reasoning_applied)       -- true when the model complied

-- And when a problem earns the thinking:
local solved = assert(client:chat(messages, { reasoning = "high" }))

One option, however the provider spells it. Asking for less reasoning never turns a working request into an error, and capabilities().reasoning_control says what a provider can honour before you ask. 

local response, err, details = client:chat(messages)

if not response then
  io.stderr:write(err, "\n")
  print(details.kind, details.status, details.retryable)
end

details.kind separates validation, transport, timeout, serialization, decoding, and HTTP failures. Credentials, tokens, and authorization headers are redacted before they reach you.

Bring your own endpoint

You do not need to wait for a named adapter when a service speaks OpenAI Chat Completions. Declare what the server supports, then run the bundled conformance suite against its real models, chat, and SSE endpoints to find out what it actually does. 

local client = require("ug-lua-llm").openai_compatible({
  base_url = "http://localhost:8000/v1",
  model = "my-model",
  api_key = os.getenv("LLM_API_KEY"), -- optional
  capabilities = {
    streaming = true,
    tools = false,
    models = true,
  },
})

Provider-native APIs stay reachable. OpenAI Responses via client:response(input), Gemini Interactions via client:interaction(input), Claude extended thinking with thinking = true, and reasoning options where the model supports them.

install

Install

Released on LuaRocks, and tested against Lua 5.1 through 5.4.

  1. Install the rock

    luarocks install ug-lua-llm

  2. Check the install

    lua -e 'local d=require"ug-lua-llm.doctor" d.print(d.run{})'

    Reports your Lua version, transport stack, JSON backend, and configured credentials without printing secrets. Then make a first request — local Ollama needs no account and no API key.

Working against the source? Clone the repository and run luarocks make ug-lua-llm-0.3.0-1.rockspec to build from a checkout instead of the released rock.

On Homebrew, use the versioned lua@5.4 formula. The unversioned formula targets Lua 5.5, which the transport dependency chain does not support yet. The installation guide covers exact setup and diagnostics.

From a checkout, the same diagnostics run as lua scripts/doctor.lua, which also accepts --provider, --endpoint, and --json.
